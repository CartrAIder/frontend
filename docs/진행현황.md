## 1. 지금까지 구현한 것

### 1.1 전체 사용자 플로우

```
로그인 / 회원가입
      │
      ▼
   홈 허브 (home) ──► 마이페이지 (mypage)
      │  ├─ 쇼핑 시작/계속하기
      │  └─ 매장 길 안내 (navigate)
      ▼
카트 QR 연결 (connect)
      ▼
장바구니 (cart, SSE 실시간)
      ▼
결제 확인 (checkout, 1탭)
      ▼
결제 완료 (complete, QR 영수증·음성)
      ▼
   홈으로 복귀
```

- **회원 세션(로그인)** 과 **카트 세션(QR)** 이 분리되어 있고, 둘 다 secure-store에 영속화됨 → 앱을 나갔다 돌아와도 복원(홈의 "쇼핑 계속하기"로 이어하기).
- 미로그인 시 `index.tsx` 라우팅 게이트가 `/login`으로, 로그인 시 `/home`으로 분기.

### 1.2 화면별 구현 내용 (10개 라우트)

| 화면 | 파일 | 구현 내용 |
|------|------|----------|
| 라우팅 게이트 | `app/index.tsx` | 세션 복원 후 로그인 여부로 `/login` · `/home` 분기 |
| 로그인 | `app/login.tsx` | 이메일·비밀번호 로그인(mock 로컬 계정 대조) + 모드 토글 |
| 회원가입 | `app/signup.tsx` | 가입 성공 시 자동 로그인, 로컬 계정 저장 |
| 홈 허브 | `app/home.tsx` | 쇼핑 시작/계속·매장 안내·마이페이지·오늘의 할인 |
| 마이페이지 | `app/mypage.tsx` | 내 정보·포인트·접근성(모드) 토글·앱 정보·로그아웃 |
| 카트 연결 | `app/connect.tsx` | expo-camera QR 스캔 + "직접 코드 입력" 대체 경로 |
| 장바구니 | `app/cart.tsx` | SSE 실시간 목록·합계, 수량 ±/삭제, "방금 추가됨" 하이라이트 |
| 결제 확인 | `app/checkout.tsx` | 주문 요약·결제 수단·최종 금액, 1탭 확인 |
| 결제 완료 | `app/complete.tsx` | 성공 표시·QR 영수증, senior 모드 음성 안내, 세션 종료 |
| 매장 길 안내 | `app/navigate.tsx` | 상품 검색·평면도(벽·입구·선반·통로)·직각 경로·할인 알림·음성 |

### 1.3 상태 관리 (Context + useReducer)

4개 Provider가 `_layout.tsx`에서 `Mode → Auth → CartSession → Cart` 순으로 중첩.

- **`ModeContext`** — `mode: 'normal' | 'senior'`(기본 normal), `useTheme()`로 현재 토큰 반환. secure-store 영속화.
- **`AuthContext`** — 회원 로그인/회원가입 세션(JWT), 영속화·복원.
- **`CartSessionContext`** — 카트 연결(cartId) 세션, 영속화·복원.
- **`CartContext`** — 장바구니 상태(useReducer). SSE 이벤트 누적, 수량·삭제는 **낙관적 업데이트** 후 REST 통보. 영속화되며, `scanIndex`로 복원 시 중복 스캔 방지. 카트 세션 종료 시 장바구니 자동 비움(캐스케이드).

### 1.4 라이브러리 계층 (`src/lib`)

- **`api.ts`** — custom fetch wrapper. secure-store JWT 자동 첨부, 에러 공통 처리. `EXPO_PUBLIC_USE_MOCK`(기본 true)로 mock/실서버 분기. mutation 함수: 회원가입·로그인·카트연결·수량변경·삭제·결제(총 6개). 실서버 엔드포인트는 `TODO(api)` 주석으로 표시.
- **`sse.ts`** — `react-native-sse` 폴리필. mock 모드에서는 상품이 하나씩 순차 "스캔"되는 시연용 스트림 재생, `fromIndex`로 이어하기 지원. 실 SSE 연결부는 스텁으로 존재(인증 방식 미확정 → Sprint 6).
- **`authStorage.ts` / `cartStorage.ts`** — secure-store 기반 세션·계정·장바구니 저장/복원.
- **`mock/products.ts` / `mock/storeMap.ts`** — 시연용 상품 카탈로그, 매장 평면도 데이터.

### 1.5 디자인 시스템 (접근성 토글)

- **`theme/tokens.ts`** — `normal` / `senior` 두 벌 토큰. 글자(본문·버튼·금액·제목·디스플레이), 터치 높이(44/56), CTA 높이, 여백, radius, 그림자, 색 팔레트, 음성 안내 여부(`voiceGuide`)까지 분리. "Toss Blue" 방향(흰 카드·은은한 그림자·파랑 브랜드), senior는 고대비(WCAG AA)·강한 테두리.
- **재사용 컴포넌트** — `Card` · `PrimaryButton` · `TextField` · `ModeToggle`. 화면은 한 벌만 만들고 스타일은 전부 토큰에서 읽음(하드코딩 없음).

### 1.6 규칙 준수 (CLAUDE.md 대비)

- ✅ 배제 라이브러리 미사용: Axios·TanStack Query·Zustand/Redux·WebSocket 없음.
- ✅ 실시간은 SSE, REST는 custom fetch wrapper.
- ✅ 화면 한 벌 + `theme[mode]` 토큰 기반 접근성.
- ✅ 재사용 컴포넌트 활용, 하드코딩된 폰트/색/그림자/radius 없음.
- ✅ API base URL·SSE 엔드포인트 상수/환경변수 분리.

### 1.7 규모·검증

- 소스 파일 25개, 약 2,830줄 (`src/` 기준).
- TypeScript strict `tsc --noEmit` **통과 (에러 0)**.
- 의존성: Expo SDK 54, React 19, expo-camera / expo-secure-store / expo-speech / react-native-sse / react-native-qrcode-svg 등.

## 2.6 부가 기능 (Sprint 6 병행 — 프론트 mock 완료)

Sprint 0~5 이후 추가된 기능들. 백엔드 없이 프론트 mock으로 전부 동작한다.

| 기능 | 화면 | 내용 |
|------|------|------|
| 상품 보기 | `products.tsx` · `product/[id].tsx` | 상품 검색(이름·브랜드·구역), 구역 칩 필터, 정렬 4종, 할인만 보기, 상세(가격·할인가·재고·설명·위치 지도·같은 구역 상품·길 안내 연결) |
| 매장 지도 | `map.tsx` | 경로 없이 지도만 표시. 구역 탭 → 그 구역 상품 목록 → 상세 이동 |
| 관리자 페이지 | `admin/*` | 대시보드(통계·품절/재고부족 경고), 상품 CRUD, 재고 ± 조절, 매장 지도 편집(구역 배치 스왑·이름·아이콘·색상), 데모 데이터 초기화 |

- **권한**: 회원 세션에 `role`이 생겼다. 회원가입 계정은 항상 `user`이고 관리자는
  mock 고정 계정(`admin@cartraider.com` / `admin1234`) 하나뿐이다. 로그인 화면에
  자동 입력 버튼이 있어 시연 시 바로 들어갈 수 있다.
- **진입점**: 홈 상단 배너 + 마이페이지 메뉴 — 둘 다 `isAdmin`일 때만 렌더링되고,
  `app/admin/_layout.tsx`가 딥링크까지 막는다.
- **데이터**: 상품·구역은 `CatalogContext`가 단일 소유하고 secure-store에 영속화된다.
  관리자가 등록/수정한 내용이 고객 화면(검색·지도·길 안내·오늘의 할인)에 즉시 반영된다.
  secure-store 값 크기 제한(2KB)을 피하려고 `catalogStorage.ts`가 JSON을 청크로 나눠 저장한다.
- **리팩터**: 매장 평면도 SVG를 `components/StoreMap.tsx`로 추출해 길 안내·매장 지도·
  관리자 편집 세 화면이 공유한다. `navigate.tsx`는 이제 `?productId=`로 목적지를 받을 수 있다.
- **남은 일**: 상품/구역 API(`/api/products`, `/api/admin/*`) 확정 시 `CatalogContext`의
  CRUD 본문만 교체하고 `catalogStorage.ts`·`DEMO_ADMIN`은 삭제한다. 역할은 백엔드가 내려준다.

## 3. 알려진 한계 / 참고

- 모든 백엔드 통신은 현재 **mock**. 실서버 명세 확정 전까지 `TODO(api)` 주석으로 표시됨.
- 관리자 변경 사항은 **기기 로컬에만** 저장된다(서버 공유 X). 상품 API 연동 시 해소.
- 결제는 실제 PG 연동 범위 밖 → **"결제 성공" 가정** 후 영수증만 발급.
- 로그인은 로컬 계정(secure-store) 대조 mock — 실 인증/토큰 갱신은 Sprint 6에서.
- REST 실패 시 롤백/알림 미구현(낙관적 업데이트만) → Sprint 6 2.3에서 보강.
